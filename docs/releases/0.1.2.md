# Hexora 0.1.2

Released October 13, 2026. Changes compared with the published
[Hexora 0.1.1](https://github.com/ZENINXOP/Hexora/releases/tag/v0.1.1) APK.

## Download and installation

- Download **Hexora.0.1.2.apk** and its `.sha256` checksum from the GitHub release.
- Android 4.4+ (minimum SDK 19), version code 13, compile SDK 36, target SDK 28.
- **New application package: `com.hexora.zenin`**, previously `app.hexora.manager`.
  This installs alongside the old package. Private settings, folder grants,
  passwords and editor sessions do not migrate automatically. Shared-storage
  files remain available when access is granted; keep the old app until any
  private files you need have been exported.
- Signed with the same private Hexora release key used for 0.1.1. Local debug
  builds use another certificate; a debug installation of `com.hexora.zenin`
  cannot be updated directly with this release.
- Telegram channel: [@Hexora_x](https://t.me/Hexora_x), also updated in About.

## New tools

### Telegram and other shared attachments

- Open attachments received through Android VIEW, SEND, SEND_MULTIPLE or ClipData.
  Telegram-style `content://` URIs no longer have to resolve to a local file path.
- The temporary read grant is used to copy attachments into Hexora's private
  **Shared files** folder, preserving safe display names and extensions.
- Duplicate filenames get separate copies. Missing permissions/files report a
  readable error; failed imports remove incomplete output. Editing changes the
  imported copy rather than the sender's original.

### Merge split applications into one APK

- **Merge to single APK** supports XAPK, APKS, APKM and ASPK bundles, selected
  loose base/split APKs, and APK-containing folders.
- Choose splits, device filters, output directory, compression, native-library
  options and signing. Package/version/base validation prevents mixed inputs.
- Nested APK members are staged safely, source files stay intact, and output
  uses an unused filename. Cancelling signing removes owned temporary output
  and V4 sidecars; incorrect signing passwords can be retried.
- OBB expansion data stays separate. Merging does not make every application
  universal or remove its external-data/runtime requirements.

### Shell script console

- Run `.sh` files through the selected available access mode, including staging
  readable scripts when necessary. Script arguments support literal quoting.
- Live stdout/stderr, line input, End input, Stop and configurable timeout;
  zero timeout means unlimited. Output is bounded to protect app memory.
- Stop terminates the launched process group. App, root and an already configured
  Shizuku backend share these controls. This is a pipe console rather than a PTY.

### File clipboard and archive search

- **Copy to clipboard**, **Cut**, **Paste** and **Clear file clipboard** for local
  files/folders and multiple selections. Paste uses the current pane without
  navigating the other pane. Existing two-pane Copy/Move remains available.
- Duplicate/ancestor selections are collapsed, collisions preserve existing
  files, and partial cuts retain unfinished items. Clipboard lifetime is the
  current app process; archive/FTP clipboard destinations are not supported.
- Search ZIP/APK entry names with recursion, case/regex, content and size filters.
- **Find in files** searches archive text, shows paths/lines/snippets and opens
  editable results with the correct archive save-back route. Password-protected
  and BOM-encoded text are supported; search can be cancelled.
- Search bounds: 500 results, entries smaller than 2 MiB, 64 MiB expanded content
  and 20,000 lines per entry. Binary/oversized preview entries are skipped and
  limits are reported.

### DEX, class and library inspection

- Add classes, import Smali/DEX, rename individual DEX classes, and rename a
  package subtree with typed-reference updates across loaded DEX files.
- Reject import/rename collisions before mutation; preserve unsaved tab changes,
  DEX membership and original/current Smali comparisons. Saved DEX references are
  re-interned correctly and original backups are retained.
- Package/class rename does not rewrite Android manifest names or reflection
  strings; those still need manual updates.
- `.class` files open in a read-only JVM bytecode viewer. **View as Java** creates
  a read-only decompiled tab for supported class/Smali input.
- Browse AAR/JAR/WAR and nested archives with logical parent navigation. Binary
  libraries offer a paged decoded-text view and Hex editor access; they are not
  treated as editable source code or executable decompilation.
- Wider DEX selection tiles with selection count, Select all and Invert selection.

## Fixes and refinements

- Target SDK changed from 37 to 28 at the owner's request for legacy direct
  storage compatibility. Folder access tries direct access, saved system grants
  and already available elevated access. Text/hex staging respects its origin
  and writes back through available access paths.
- Password prompts, retry/cancel, browsing, extraction and edit/save for AES and
  ZipCrypto ZIPs. Edited entries retain encryption and unchanged original backups.
  Passwords remain in a bounded process-only cache, including canonical aliases.
- Returning from editors keeps pane scroll anchors and filters. Archive folder
  sort settings are isolated by archive/path. Refresh gesture behavior refined.
- Cancellable background editor loading, bounded large-file editing/previews,
  paged binary text, encoding/BOM/newline preservation, session recovery and
  clearer Save/dirty/Reload behavior. Reload asks before discarding unsaved text.
- Archive edits use validated staging and backups; results from closed or
  minimized tabs return correctly. Non-APK archives do not offer APK signing.
- ZIP-to-folder Move waits for source removal before refreshing. APK alignment
  handles structured ZIP extras and 16 KiB-aligned input without old parser
  overreads. Optional V4 sidecars follow their final APK names.
- Refined Open with tool grid, MIME categories/search, file-format icons, folder
  app badges, editor colors and layouts in light/dark themes.
- Material progress indicators and measurable operation progress, including
  completed/remaining percentages and background notifications.
- APK signature-tool compatibility refinements and LSPatch integration, with
  lightweight, advanced and explicitly experimental native modes. Coverage varies
  by application; no universal signature-check compatibility is claimed.

## Validation and limits

The signed release build, signature/alignment checks, exact test totals and
release smoke results are recorded in [the release validation report](../../qa/RELEASE_0.1.2.md).
Earlier focused MuMu runs cover Telegram-shaped URI grants, split merging,
scripts, encrypted ZIPs, DEX actions, clipboard/search and editor sessions.
Detailed reports retain both failed attempts and corrected checks.

- Testing used owned disposable fixtures on MuMu Android 15/API 35. Telegram's
  real account/files and universal compatibility across phones are not claimed.
- Android/data and Android/obb restrictions still apply. Target SDK 28 does not
  itself grant access to another app's protected files. Vivo blocked the supplied
  PUBG path with direct/system-picker access; root or separately configured
  Shizuku may still be needed. No Shizuku installation is required or performed.
- Creating encrypted archives and password-protected RAR/7z support are not added.
- The in-app updater remains inactive until its repository setting is configured.
