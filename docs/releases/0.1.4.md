# Hexora 0.1.4

Changes since [Hexora 0.1.3](https://github.com/ZENINXOP/Hexora/releases/tag/v0.1.3).

## Download

- **Hexora.0.1.4.apk** is the main app; other APK assets are optional tool packs.
- Package `com.hexora.zenin`, version code 15, Android 4.4+; target SDK 28.
- Signed with the existing Hexora release certificate for in-place updates.
- Verify the download with `Hexora.0.1.4.apk.sha256` or `SHA256SUMS`.
- Optional tool packs and their signed catalog are unchanged from 0.1.3.

## Interface and editor preferences

- Two consistent themes, Light and Dark, with a larger animated sidebar toggle.
- Compact sidebar sections, clearer storage rows and updated folder icons.
- Redesigned settings with search, collapsible sections and access status.
- Editor font, line-number, wrapping and indentation preferences now apply
  consistently. Added validated TextMate JSON syntax import and improved
  shortcut management.
- The selection-menu preferences use readable theme colors for icons, labels,
  checkboxes, dialogs and drag highlights. Saved menu changes reload in the editor.
- Simplified DEX controls and improved menu and drawer contrast.

## Files, access and reliability

- Archive entry properties show available metadata inside APKs and folders.
- Reuse existing root/Shizuku grants, request Shizuku authorization when needed,
  and resume pending supported operations after access becomes available.
- Corrected concrete APK/Smali compiler dispatch and format handling defects;
  staged output and failure recovery protect previous files during saves.
- Reduced repeated metadata work during sorting, filtering and icon loading.
- Buffered hex searches, bounded image previews and background media metadata
  work reduce main-thread work and unnecessary allocations.
- Additional cancellation, stale-callback and resource-cleanup fixes across
  image, media, archive, search and editor workflows.

## Validation

Build, test, signing and runtime evidence is recorded in
[the release validation report](../../qa/RELEASE_0.1.4.md).
The original reported APK-build crash had no failing APK or trace, so reproducing
that specific issue remains unverified. Root/Shizuku behavior requires testing
with those services on a supported device.
