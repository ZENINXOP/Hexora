## Signature outcomes

The owned fixture checks legacy signatures, current/history SigningInfo,
multiple/past signer booleans, absent flags, other-package behavior and reflection.
Original and patched certificates differ, so querying the original signer is a
meaningful acceptance check rather than signing everything with the same key.

| Test | Observed result |
| --- | --- |
| Original plain fixture | All eight checks pass |
| Java patch → sign → install → launch | Seven supported checks pass; reflection remains unsupported, as expected |
| Advanced patch → sign → install → launch | All eight checks pass, including reflection |
| Native mode on a Java-only APK | Clear arm64 eligibility error, no output |
| Patching an already patched APK | Clear rejection, no additional output |
| Original arm64 JNI fixture on MuMu | Certificate checks and native APK CRC pass |
| Advanced and experimental arm64 JNI outputs on MuMu | Certificate checks pass; native APK CRC fails in both modes |
| Original and Advanced x86_64 JNI fixtures | Certificate checks and native APK CRC pass |

The JNI test reads Android's actual installed outer APK path supplied by the host,
using native `open`/`read`, and compares the CRC with the original signed APK.
It does not rely on a Java `sourceDir` that hooks could already rewrite. It is a
file-redirection test, not certification of every native certificate parser or
direct syscall. The x86_64 result verifies common native reads on MuMu's native
architecture. The arm64 failures are retained, not counted as passes. During the
experimental ARM run, the runtime logs:

`enableSvcRedirect: raw-svc apk-read redirect is implemented on arm64 only`

This supports a translation/process architecture limitation. Physical arm64
native coverage and direct syscalls still require their own validation. No
universal signature bypass is claimed.

The Xian Esp 2.1.0 original, Advanced output and experimental output all reached
the same IntroActivity / opening-video screen on MuMu. The earlier `XDEC:8`
bootstrap crash was not observed in those launches. This verifies startup only;
later protected features, login, server checks and other devices were not tested.
The emulator initially had no Xian installation; only these newly installed test
copies were replaced. Existing phone data was not modified.

Independent ZIP checks confirm the embedded original equals the complete input,
